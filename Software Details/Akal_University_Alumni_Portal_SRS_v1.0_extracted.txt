1. Introduction

The Akal University Alumni Portal is a centralized web-based platform designed to connect Akal University, its alumni, current students and the university administration. The portal will provide a professional public-facing alumni website as well as authenticated dashboards for alumni, students, administrators and super administrators.

The system is intended to transform alumni management from scattered/manual communication into a structured digital network. It will support alumni registration and verification, profiles, alumni directory, batchmates, events, reunions, jobs, internships, mentorship, chapters, alumni stories, digital alumni identification, notifications and analytics.

2. Purpose

The primary purposes of the system are:

Create a verified digital database of Akal University alumni.

Allow visitors to discover the university's alumni community without mandatory login.

Provide secure personalized services after alumni/student login.

Help alumni reconnect with batchmates, classmates and professional contacts.

Provide career opportunities, internships, mentorship and networking.

Manage alumni events, reunions and registrations digitally.

Showcase distinguished alumni and alumni achievements.

Enable the university to publish announcements, stories, galleries and opportunities.

Provide administrators with dashboards, verification tools, reports and audit logs.

Create a foundation for future mobile applications and advanced integrations.

Automatic verification from external government databases.

6. Overall System Workflow

The high-level workflow is:

Public visitor opens the Alumni Portal.

Visitor can browse public content without creating an account.

An alumni candidate selects Join Alumni / Register.

Candidate submits academic and professional information.

System validates required fields and creates a pending account.

Admin verifies the alumni record using university information.

Approved alumni can log in and access the personalized dashboard.

Alumni can complete their profile, connect with batchmates, register for events, apply for jobs and participate in mentorship.

Students can log in and use student-specific networking and mentorship features.

Admins manage content, users, events, jobs and verification.

Super Admin controls administrators, permissions, settings and audit activities.

14. Business Rules

Only approved alumni accounts are considered verified alumni.

Inactive/rejected users cannot log in to restricted areas.

Only active approved alumni should appear in the public directory.

Public profiles must never expose private contact information unless explicitly configured as public.

Only authorized admins can approve alumni registrations.

Jobs and events submitted by alumni may require admin approval before publication.

Event registration must respect event capacity and eligibility rules.

A user should not register twice for the same event.

Only eligible verified mentors can receive mentorship requests.

Only Super Admin can create or modify high-privilege admin accounts unless delegated.

Deleted records should preferably be soft-deleted when historical/audit information is important.

Critical actions must be recorded in activity logs.

17. Security Requirements

Passwords must be stored using a strong one-way password hashing mechanism.

HTTPS must be used in production.

All authenticated endpoints must verify authentication and role permissions.

Input validation and sanitization must be applied to all user-controlled data.

Protection against SQL injection must be provided through CodeIgniter query builder/parameterized queries.

CSRF protection should be enabled where applicable for cookie/session-based web forms.

File uploads must validate file type, size and safe filename/path.

Authentication sessions/tokens must expire appropriately.

Rate limiting should be applied to login and sensitive endpoints.

Private profile fields must not be returned through public APIs.

Administrative actions must be logged.

Regular database and uploaded-file backups must be maintained.

Error responses must not expose database credentials, stack traces or sensitive server information.

A visitor can browse the public portal without logging in.

A visitor cannot access private alumni information.

An alumni candidate can register successfully.

Approved alumni can log in and manage their profile.

Alumni directory supports required search/filter operations.

Batchmates can be discovered based on batch/course/department.

APIs return consistent authenticated/unauthenticated responses.

26. Conclusion

The proposed Akal University Alumni Portal will provide a centralized, secure and scalable digital ecosystem for alumni engagement. The portal will keep important public information accessible without login while reserving personalized actions such as networking, event registration, mentorship and applications for authenticated users. The architecture is designed to support future expansion into a mobile application, university integrations, advanced analytics and AI-assisted alumni services.

The recommended implementation approach is to build the backend as a CodeIgniter 4 REST API with MySQL and a responsive React/Bootstrap frontend. Development should be carried out module-by-module, with authentication, alumni verification and core directory functionality implemented before advanced engagement features.
